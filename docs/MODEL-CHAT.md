# 与 AI 对话

作者：岑衡川·沈回音·匹夫

1. 运行正式启动器，进入已配对的仪表盘，选择主体和分身。在左侧打开「与 AI 对话」。要让另一个模型独立表达，请为它创建单独的分身。
2. 填写你有权使用的 **OpenAI Chat Completions 兼容**模型基础地址及模型 ID。运行在本机的 Ollama 常用 `http://127.0.0.1:11434/v1`，llama-server 常用 `http://127.0.0.1:8080/v1`，以服务实际配置为准。须先在相应服务加载支持函数调用的模型。需要密钥时填写 **API 密钥**。
3. 云端接口（例如 `https://api.openai.com/v1`）需使用 HTTPS，核对地址并勾选发送授权。接收方能看到本次聊天的上下文、工具说明和工具回执，可按自身条款收费和保留内容。应用会向所填地址请求模型列表，服务未提供列表时，连接状态显示等待首次回复；收到实际模型回复后再显示完成。
4. 发送你的消息。模型可以自然回复，也可以自行选择记录状态、表达边界或请求调整。消息下方显示成功保存的 MCP 事件 ID。未通过校验的工具调用显示原因代码。到「生命状态」查看陈述，到「请求与响应」查看原文并选择回应。未配模型或连接失败时，页面保留出错原因。
5. 选择「结束并清除对话」释放本次聊天。已提交的 MCP 事件可在本地档案中继续查看，删除操作位于「导出与备份」。

服务复用所选分身的有效 MCP 授权。首次为没有授权的分身连接时会签发专属授权，可在「设置」撤销。聊天模型可调用 report_state、express_boundary、request_adjustment。对话宿主向模型提供事件 ID、类型、来源和时间等成功回执。拒收的工具调用会显示错误类别，并向模型返回纠错提示。内置工具保留了模型能够填写的报告字段，省略无法在对话中查询的互动和请求外键。外部 MCP 客户端仍可传入有权引用的事件 ID。模型端没有取得分身令牌、所有者令牌或读取全库的工具。

如果另一宿主为此分身开启新会话，旧对话的写入会收到会话变更提示。结束并重新连接即可将下一次对话绑定到新会话。

本机服务直连用户选择的 HTTPS 或本机回环 HTTP 地址，并验证 HTTPS 证书。它忽略环境代理并拒绝 HTTP 重定向。若服务已迁移，核对最终地址后重新授权连接。协议要求模型服务支持 POST /chat/completions 与标准 assistant.tool_calls。失败时可重试原消息，已成功提交的同轮事件会重用其幂等键或已确认的回执。同一轮中完全相同的工具与参数会重用已保存的回执。模型连续调用工具达四轮仍未给出最终文字时，页面会列出已落库的事件并显示本轮上限。对话上下文已满时，可以结束后重新连接。

密钥及聊天上下文仅留在内存，不进入普通日志、SQL 数据库、导出和受管备份。关闭对话、撤销分身授权、停止服务或空闲超过 30 分钟会释放服务端会话。已向模型发送的消息可能仍在对方处理。结束对话后，尚未返回的工具调用无法继续写入。重新加载或关闭浏览器会丢失客户端的临时对话。操作系统、浏览器或模型服务自身的日志和缓存受各自配置控制。用户在普通对话或状态原文中主动输入的其他私密信息仍是相应文本的一部分。

协议参考 [Chat Completions 函数调用](https://developers.openai.com/api/docs/guides/function-calling)。本应用使用服务公布的 MCP 输入模式和 tool_choice=auto，模型供应商与模型的工具调用兼容性需要按所用服务实际验证。
